    你的理解方向是对的：卷积本质上是一个线性运算，因此一定可以写成矩阵乘法。

    但这里有一个很重要的区分：

    • 从数学上看，可以把卷积核展开成一个巨大的 Toeplitz / Block-Toeplitz 卷积矩阵；
    • 从实际 CPU/GPU/NPU 实现看，通常不会真的构造这个巨大稀疏 Toeplitz 矩阵；
    • 最经典的工程方法是 im2col + GEMM：把输入的每个卷积窗口展开成列，然后调用高效矩阵乘法；
    • 更现代的实现则常进一步做成 implicit GEMM：连 im2col 矩阵都不真正写回内存，而是在数据进入 MAC 阵列时动态产生。

    所以你可以把演进关系理解成：

    \[ \boxed{ \text{Toeplitz数学表示} \rightarrow \text{im2col + GEMM} \rightarrow \text{implicit GEMM / direct convolution} } \]

    1. 先从最简单的 1D 卷积开始¶

    假设输入

    \[ x= \begin{bmatrix} x_0&x_1&x_2&x_3&x_4 \end{bmatrix}^T \]

    卷积核长度为 3：

    \[ w= \begin{bmatrix} w_0&w_1&w_2 \end{bmatrix} \]

    先暂时不考虑 padding，stride=1。

    深度学习框架里的 Conv 实际通常做的是 cross-correlation（互相关），即不进行 kernel 翻转：

    \[ y_0=w_0x_0+w_1x_1+w_2x_2 \]
    \[ y_1=w_0x_1+w_1x_2+w_2x_3 \]
    \[ y_2=w_0x_2+w_1x_3+w_2x_4 \]

    把它写成矩阵：

    \[ \begin{bmatrix} y_0\\ y_1\\ y_2 \end{bmatrix} = \begin{bmatrix} w_0&w_1&w_2&0&0\\ 0&w_0&w_1&w_2&0\\ 0&0&w_0&w_1&w_2 \end{bmatrix} \begin{bmatrix} x_0\\ x_1\\ x_2\\ x_3\\ x_4 \end{bmatrix} \]

    中间这个矩阵就是典型的 Toeplitz-like 卷积矩阵：

    \[ T(w)= \begin{bmatrix} w_0&w_1&w_2&0&0\\ 0&w_0&w_1&w_2&0\\ 0&0&w_0&w_1&w_2 \end{bmatrix} \]

    于是：

    \[ \boxed{y=T(w)x} \]

    所谓“卷积变成矩阵乘法”，最直接的数学表达就是这个。

    注意这里有大量：

    • 0；
    • 重复的 \(w_0,w_1,w_2\)。

    这会成为后面的关键问题。

    2. 2D 卷积同样可以这么干¶

    现在考虑一个非常具体的例子。

    输入：

    \[ X= \begin{bmatrix} 1&2&3\\ 4&5&6\\ 7&8&9 \end{bmatrix} \]

    卷积核：

    \[ W= \begin{bmatrix} a&b\\ c&d \end{bmatrix} \]

    stride=1，padding=0。

    输出尺寸是：

    \[ 2\times2 \]

    四个输出分别为：

    \[ y_{00}=a\cdot1+b\cdot2+c\cdot4+d\cdot5 \]
    \[ y_{01}=a\cdot2+b\cdot3+c\cdot5+d\cdot6 \]

    等等。

    把输入 flatten：

    \[ x= \begin{bmatrix} 1&2&3&4&5&6&7&8&9 \end{bmatrix}^{T} \]

    那么：

    \[ \begin{bmatrix} y_{00}\\ y_{01}\\ y_{10}\\ y_{11} \end{bmatrix} = \begin{bmatrix} a&b&0&c&d&0&0&0&0\\ 0&a&b&0&c&d&0&0&0\\ 0&0&0&a&b&0&c&d&0\\ 0&0&0&0&a&b&0&c&d \end{bmatrix} \begin{bmatrix} 1\\2\\3\\4\\5\\6\\7\\8\\9 \end{bmatrix} \]

    这个 \(4\times9\) 矩阵就是二维情况下的卷积矩阵。

    严格来说，二维卷积对应的结构通常叫：

    \[ \boxed{\text{Block Toeplitz with Toeplitz Blocks}} \]

    也经常简称 BTTB。

    你可以观察到它的本质：

    每产生一个新的 output pixel，就把 kernel 在输入空间平移一下。

    因此矩阵中的权重也跟着发生规则性的平移。

    3. 但 AI 芯片通常不会真的这么做¶

    这里就是非常关键的一点。

    假如真实网络里：

    \[ C_{in}=64 \]
    \[ C_{out}=128 \]

    输入：

    \[ H=W=224 \]

    kernel：

    \[ 3\times3 \]

    那么如果真构造：

    \[ y=T(W)x \]

    这个矩阵的规模大约是：

    \[ (C_{out}H_{out}W_{out}) \times (C_{in}H_{in}W_{in}) \]

    也就是数量级：

    \[ (128\times222\times222) \times (64\times224\times224) \]

    这是一个极其荒谬的大矩阵，而且其中绝大多数元素都是 0。

    所以：

    \[ \boxed{\text{Toeplitz主要是数学理解，而不是实际存储形式}} \]

    实际工程上更常使用另一种等价变换。

    4. 真正经典的方法：im2col¶

    核心想法变成：

    与其把 kernel 复制很多遍，不如把 input 的每个 receptive field 抽出来。

    还是刚才的：

    \[ X= \begin{bmatrix} 1&2&3\\ 4&5&6\\ 7&8&9 \end{bmatrix} \]

    kernel：

    \[ W= \begin{bmatrix} a&b\\ c&d \end{bmatrix} \]

    四个 receptive field 是：

    第一个窗口¶

    \[ \begin{bmatrix} 1&2\\ 4&5 \end{bmatrix} \rightarrow \begin{bmatrix} 1\\2\\4\\5 \end{bmatrix} \]

    第二个窗口¶

    \[ \begin{bmatrix} 2&3\\ 5&6 \end{bmatrix} \rightarrow \begin{bmatrix} 2\\3\\5\\6 \end{bmatrix} \]

    依次类推。

    最后得到：

    \[ X_{\mathrm{col}} = \begin{bmatrix} 1&2&4&5\\ 2&3&5&6\\ 4&5&7&8\\ 5&6&8&9 \end{bmatrix} \]

    注意：

    每一列对应一个 convolution window。

    kernel 也 flatten：

    \[ W_{\mathrm{row}} = \begin{bmatrix} a&b&c&d \end{bmatrix} \]

    那么：

    \[ \boxed{ Y_{\mathrm{row}} = W_{\mathrm{row}}X_{\mathrm{col}} } \]

    即：

    \[ \begin{bmatrix} y_{00}&y_{01}&y_{10}&y_{11} \end{bmatrix} = \begin{bmatrix} a&b&c&d \end{bmatrix} \begin{bmatrix} 1&2&4&5\\ 2&3&5&6\\ 4&5&7&8\\ 5&6&8&9 \end{bmatrix} \]

    这就是：

    \[ \boxed{\text{im2col + GEMM}} \]

    其中 GEMM 就是 General Matrix-Matrix Multiplication。

    5. 推广到真正的 CNN¶

    真正的卷积有：

    \[ X\in\mathbb R^{C_{in}\times H\times W} \]

    卷积核：

    \[ W\in \mathbb R^{ C_{out}\times C_{in}\times K_h\times K_w } \]

    输出：

    \[ Y\in \mathbb R^{ C_{out}\times H_{out}\times W_{out} } \]

    定义：

    \[ K=C_{in}K_hK_w \]

    以及：

    \[ N=H_{out}W_{out} \]

    kernel 展开¶

    每一个 output channel 都对应一个 kernel：

    \[ C_{in}\times K_h\times K_w \]

    flatten 后长度：

    \[ K=C_{in}K_hK_w \]

    一共 \(C_{out}\) 个 kernel，于是：

    \[ W_{\mathrm{mat}} \in \mathbb R^{C_{out}\times K} \]

    输入 im2col¶

    每一个 output pixel 对应输入里的一个：

    \[ C_{in}\times K_h\times K_w \]

    receptive field。

    把它展开成长度为：

    \[ K=C_{in}K_hK_w \]

    的向量。

    共有：

    \[ N=H_{out}W_{out} \]

    个 output pixel。

    于是：

    \[ X_{\mathrm{col}} \in \mathbb R^{K\times N} \]

    最后直接 GEMM¶

    \[ \boxed{ Y_{\mathrm{mat}} = W_{\mathrm{mat}} X_{\mathrm{col}} } \]

    矩阵尺寸为：

    \[ \underbrace{ [C_{out}\times K] }_{Weights} \; \times \; \underbrace{ [K\times H_{out}W_{out}] }_{Activations} \]

    得到：

    \[ \underbrace{ [C_{out}\times H_{out}W_{out}] }_{Output} \]

    最后 reshape 成：

    \[ C_{out}\times H_{out}\times W_{out} \]

    即可。

    这是整个经典 CNN → GEMM 转换中最值得记住的一条式子：

    \[ \boxed{ [C_{out}\times(C_{in}K_hK_w)] \times [(C_{in}K_hK_w)\times(H_{out}W_{out})] } \]

    6. 从单个输出元素看，就更加明显了¶

    卷积本来的定义是：

    \[ Y[c_o,h,w] = \sum_{c_i} \sum_{k_h} \sum_{k_w} W[c_o,c_i,k_h,k_w] X[c_i,h+k_h,w+k_w] \]

    把三个 reduction dimension：

    \[ (c_i,k_h,k_w) \]

    合并成一个：

    \[ k \]

    那么：

    \[ Y[c_o,n] = \sum_k W_{\mathrm{mat}}[c_o,k] X_{\mathrm{col}}[k,n] \]

    这不就是矩阵乘法：

    \[ C_{ij} = \sum_k A_{ik}B_{kj} \]

    吗？

    换句话说：

    CNN 卷积所谓“转成 GEMM”，并没有什么神秘的数学变换，本质上只是把三个求和维度合并成矩阵乘法的 \(K\) 维。

    7. 从 AI 加速器视角看这件事¶

    这时候就非常有意思了。

    假设：

    \[ W_{\mathrm{mat}} : [M\times K] \]
    \[ X_{\mathrm{col}} : [K\times N] \]

    其中：

    \[ M=C_{out} \]
    \[ K=C_{in}K_hK_w \]
    \[ N=H_{out}W_{out} \]

    卷积立刻变成经典：

    \[ \boxed{ [M\times K]\times[K\times N] } \]

    这正是 TPU / NPU / Tensor Core / systolic array 最喜欢的计算形式。

    例如一个脉动阵列：

              Activation
             ↓
       ↓   ↓   ↓   ↓
     +---+---+---+---+
W -> |MAC|MAC|MAC|MAC|
     +---+---+---+---+
     |MAC|MAC|MAC|MAC|
     +---+---+---+---+
     |MAC|MAC|MAC|MAC|
     +---+---+---+---+
     |MAC|MAC|MAC|MAC|
     +---+---+---+---+

    每个 PE 核心操作就是：

    \[ acc \leftarrow acc+w\times x \]

    整个阵列实际上就在计算：

    \[ C=A B \]

    因此在硬件层面：

    \[ \boxed{ Conv \rightarrow GEMM \rightarrow 大量规则的 MAC } \]

    这也是 AI accelerator 特别喜欢 GEMM 的原因：

    • 控制规则；
    • 数据访问规律；
    • MAC 利用率高；
    • 容易做 SIMD / vector；
    • 容易做 systolic array；
    • 容易进行 weight reuse；
    • activation reuse；
    • partial sum reuse。

    8. 为什么 im2col 还是“不够完美”？¶

    im2col 虽然解决了 Toeplitz 大量零的问题，但它产生了另外一个问题：

    \[ \boxed{\text{input duplication}} \]

    例如一个：

    \[ 3\times3 \]

    卷积。

    一个 input pixel 可能同时属于周围最多 9 个 convolution window。

    因此 im2col 后，它可能被复制：

    \[ \sim9 \]

    次。

    假设：

    \[ X: C_{in}\times H\times W \]

    原始数据量：

    \[ C_{in}HW \]

    而 im2col：

    \[ X_{\mathrm{col}}: (C_{in}K_hK_w) \times (H_{out}W_{out}) \]

    stride=1 且尺寸接近不变时：

    \[ \frac{ |X_{\mathrm{col}}| }{ |X| } \approx K_hK_w \]

    所以对于：

    \[ 3\times3 \]

    大约可能膨胀：

    \[ 9\times \]

    对于：

    \[ 5\times5 \]

    则可能：

    \[ 25\times \]

    这对于 AI 加速器非常糟糕，因为很多时候：

    \[ \boxed{\text{数据搬运比 MAC 本身贵得多}} \]

    因此现代实现通常不愿意真的：

    DRAM
 ↓
构造巨大 im2col
 ↓
写回 SRAM/DRAM
 ↓
再读取
 ↓
GEMM

    9. 所以出现了 implicit GEMM¶

    这是现代实现中非常重要的概念。

    仍然在逻辑上认为存在：

    \[ X_{\mathrm{col}} \]

    但：

    \[ \boxed{\text{根本不真正构造 }X_{\mathrm{col}}} \]

    而是硬件/软件根据：

    \[ (c_i,k_h,k_w,h_{out},w_{out}) \]

    直接计算原始 input 地址。

    比如逻辑上 GEMM 需要：

    \[ X_{\mathrm{col}}[k,n] \]

    硬件把：

    \[ k \]

    解码成：

    \[ (c_i,k_h,k_w) \]

    把：

    \[ n \]

    解码成：

    \[ (h_{out},w_{out}) \]

    然后直接读取：

    \[ X[ c_i,\, h_{out}S_h+k_hD_h-P_h,\, w_{out}S_w+k_wD_w-P_w ] \]

    这里：

    • \(S\)：stride；
    • \(D\)：dilation；
    • \(P\)：padding。

    于是：

    原始 Activation SRAM
        │
        │ address generator
        ↓
   patch element
        │
        ↓
   MAC / GEMM Array

    而不是：

    Activation
    ↓
显式 im2col
    ↓
巨大临时矩阵
    ↓
GEMM

    这就是：

    \[ \boxed{\text{Implicit GEMM}} \]

    可以把它理解成：

    数学上 im2col，物理上不 im2col。

    这是特别重要的一句话。

    10. Toeplitz 和 im2col，其实是同一件事的两个视角¶

    这一点很值得仔细理解。

    Toeplitz 版本是：

    \[ \boxed{ y=T(w)x } \]

    也就是：

    复制 / 平移 kernel。

    而 im2col 是：

    \[ \boxed{ y=wX_{\mathrm{col}} } \]

    也就是：

    复制 / 平移 input window。

    本质上它们描述的是完全一样的线性运算。

    可以画成：

                 同一个卷积
                 │
        ┌────────┴────────┐
        ↓                 ↓
   展开 kernel         展开 input
        ↓                 ↓
  Toeplitz matrix       im2col
        ↓                 ↓
      T(w)x             W Xcol

    但是后者更适合：

    \[ \boxed{\text{Dense GEMM}} \]

    因此工程实践主要采用第二种视角。

    11. 一个对 AI 芯片很重要的观察：1×1 Conv¶

    如果：

    \[ K_h=K_w=1 \]

    那么：

    \[ K=C_{in} \]

    根本不需要真正的 window extraction。

    每个 spatial pixel 就是一个长度：

    \[ C_{in} \]

    的向量。

    于是：

    \[ W: C_{out}\times C_{in} \]

    输入 reshape：

    \[ X: C_{in}\times HW \]

    直接：

    \[ \boxed{ Y=WX } \]

    所以：

    \[ \boxed{ 1\times1\ Conv \approx 纯 GEMM } \]

    这也是为什么 \(1\times1\) Conv 对矩阵乘加硬件非常友好。

    12. Depthwise Conv 又是另一个极端¶

    普通卷积：

    \[ C_{out}\times C_{in}\times K_h\times K_w \]

    每个 output channel 都和所有 input channels 相连。

    但 Depthwise Conv：

    \[ \text{每个 channel 单独卷积} \]

    因此它相当于非常多个：

    \[ 1\times K_hK_w \]

    的小矩阵乘法。

    如果硬塞进大型 GEMM array：

    GEMM 的 \(M\)、\(K\) 等维度可能太小，PE 利用率非常差。

    所以 Depthwise Conv 通常更适合：

    • specialized convolution unit；
    • vector unit；
    • direct convolution；
    • 专门的数据流。

    这也是为什么：

    “所有卷积都转 GEMM”在数学上成立，但在硬件上并不一定最优。

    13. 真正的 AI Processor 会有哪些选择？¶

    你后续研究硬件加速器时，大致会见到这几类。

    ① Explicit im2col + GEMM¶

    最容易理解：

    Conv
 ↓
im2col
 ↓
GEMM
 ↓
reshape

    优点：

    • 简单；
    • 可以复用成熟 GEMM；
    • CPU 上特别经典。

    缺点：

    • 数据膨胀；
    • memory traffic 大。

    ② Implicit GEMM¶

    Conv
 ↓
逻辑上 im2col
 ↓
地址生成器直接产生 patch
 ↓
GEMM array

    优点：

    • 不存储巨大 im2col；
    • 仍然可以利用高性能矩阵乘单元。

    这是非常重要的现代方案。

    ③ Direct Convolution¶

    直接按照：

    \[ (c_o,h,w,c_i,k_h,k_w) \]

    这些 loop 来调度。

    例如伪代码：

    for (co)
  for (h)
    for (w)
      for (ci)
        for (kh)
          for (kw)
            Y[co][h][w] +=
                W[co][ci][kh][kw]
              * X[ci][h+kh][w+kw];

    硬件通过：

    • loop tiling；
    • loop interchange；
    • data reuse；
    • systolic / spatial mapping；

    直接实现这些 nested loops。

    这种视角在 Eyeriss 一类 accelerator/dataflow 研究里尤其重要。

    ④ Winograd¶

    对于典型：

    \[ 3\times3 \]

    卷积，可以通过数学变换减少乘法次数：

    \[ \boxed{\text{Winograd convolution}} \]

    核心思想大致是：

    \[ Y=A^T[ (GWG^T)\odot(B^TXB) ]A \]

    先 transform input 和 kernel，然后大量使用 element-wise multiplication。

    优点：

    \[ \text{减少 MAC} \]

    缺点：

    • transformation overhead；
    • numerical stability；
    • 对 kernel size 有限制；
    • quantization 下也有一些问题。

    ⑤ FFT convolution¶

    利用：

    \[ x*w = \mathcal F^{-1} ( \mathcal F(x)\mathcal F(w) ) \]

    对于特别大的 kernel 有优势。

    但 CNN 常见：

    \[ 3\times3,\quad1\times1 \]

    通常不一定划算。

    14. 如果站在 AI 加速器设计者的角度，真正的问题其实不是“能不能变成 GEMM”¶

    答案肯定是：

    \[ \boxed{\text{能}} \]

    真正的问题是：

    怎么映射，才能最大化数据复用并最小化数据搬运？

    也就是类似：

    \[ \text{Conv Tensor} \]

    ↓

    \[ \text{loop nest} \]

    ↓

    \[ \text{tiling} \]

    ↓

    \[ \text{mapping onto PE array} \]

    ↓

    \[ \text{dataflow} \]

    这就会引出 AI accelerator 里非常核心的一套概念：

    • Weight Stationary
    • Output Stationary
    • Input Stationary
    • Row Stationary
    • spatial mapping
    • temporal mapping
    • loop tiling
    • PE utilization
    • NoC
    • SRAM hierarchy
    • reuse factor

    实际上对于 AI 芯片：

    \[ \boxed{ \text{MAC 本身通常不是最难的，数据怎么移动才是核心。} } \]

    15. 给你建立一个“三级理解模型”¶

    我比较建议以后脑子里同时保留这三个视角：

    数学视角¶

    \[ \boxed{ y=T(w)x } \]

    卷积是一个具有 Toeplitz / Block-Toeplitz 结构的线性变换。

    这是理解卷积线性代数性质最好的方式。

    软件实现视角¶

    \[ \boxed{ Y=W_{\mathrm{mat}}X_{\mathrm{col}} } \]

    也就是：

    \[ \boxed{\text{im2col + GEMM}} \]

    这是理解 BLAS / GEMM-based convolution 最好的方式。

    AI 芯片视角¶

    通常更接近：

    \[ \boxed{ \text{Tensor Contraction} \rightarrow \text{Tiling / Mapping} \rightarrow \text{MAC Array} } \]

    逻辑上可以等价成 GEMM，但未必真的生成那个矩阵。

    16. 顺便和 ConvTranspose2d 联系起来¶

    这里还有一个非常漂亮的联系。

    刚才我们说普通卷积可以写成：

    \[ y=T(w)x \]

    那么线性代数中的转置算子就是：

    \[ x'=T(w)^Ty \]

    这正是理解 Transposed Convolution 名字来源的一个非常好的方式。

    所以 ConvTranspose2d 里的：

    Transpose

    不是“把 kernel 矩阵转置一下”，而是：

    \[ \boxed{ \text{把整个 convolution linear operator }T(w)\text{ 转置} } \]

    这也解释了为什么 ConvTranspose 会把一个 output pixel 的信息“scatter”回多个 input spatial positions——因为普通卷积是 gather receptive field，而转置算子反过来就是 scatter accumulation。

    最后把整个知识结构压缩成一张图¶

                     CNN Convolution
                       │
           数学上是线性变换
                       │
                       ↓
              y = T(W) x
                       │
          Toeplitz / Block-Toeplitz
                       │
            但矩阵巨大、稀疏
                       ↓
              换一种展开方式
                       │
                       ↓
                    im2col
                       │
        Wmat × Xcol = Ymat
                       │
                       ↓
                     GEMM
                       │
             ┌─────────┴─────────┐
             ↓                   ↓
       explicit im2col      implicit GEMM
             │                   │
        存临时矩阵          动态地址生成
             │                   │
             └─────────┬─────────┘
                       ↓
                 MAC / PE Array
                       │
          ┌────────────┼───────────┐
          ↓            ↓           ↓
   Weight Stationary  OS        Row Stationary

    所以如果你现在只记住一句话，可以记：

    \[ \boxed{ \text{卷积数学上可以写成 Toeplitz 矩阵乘法；} \newline \text{经典实现是 im2col + GEMM；} \newline \text{现代 AI 加速器往往采用 implicit GEMM 或直接数据流实现，避免真的构造这些矩阵。} } \]

    而对你接下来学习 AI/Transformer/CNN 加速器来说，下一层最值得继续深入的，其实就是把

    \[ [C_{out}\times C_{in}K_hK_w] \times [C_{in}K_hK_w\times H_{out}W_{out}] \]

    这个 GEMM 真正映射到一个例如 \(16\times16\) 的 systolic array 上：每个 PE 算什么、权重/activation 怎么流、partial sum 放哪里、如何 tiling，以及 Weight Stationary / Output Stationary 到底是什么意思。这个会直接进入 AI 芯片架构的核心。
