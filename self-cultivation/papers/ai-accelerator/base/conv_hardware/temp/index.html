    可以。第二阶段我们就专门回答一个承上启下的问题：

    已经知道卷积可以写成 \(y=T(W)x\)，为什么真正的 CPU/GPU/NPU 基本不会显式构造这个 Toeplitz 卷积矩阵？又是怎样一步步演化成 im2col + GEMM 的？

    这一阶段的核心不是“再学一种数学表示”，而是理解：

    \[ \boxed{ \text{数学上等价} \neq \text{计算机上高效} } \]

    第二阶段：为什么不用显式 Toeplitz，以及 im2col 是怎么自然产生的¶

    先回到上一阶段的二维例子。

    输入：

    \[ X= \begin{bmatrix} x_{00}&x_{01}&x_{02}\\ x_{10}&x_{11}&x_{12}\\ x_{20}&x_{21}&x_{22} \end{bmatrix} \]

    kernel：

    \[ W= \begin{bmatrix} a&b\\ c&d \end{bmatrix} \]

    Toeplitz 展开后：

    \[ \begin{bmatrix} y_{00}\\ y_{01}\\ y_{10}\\ y_{11} \end{bmatrix} = \underbrace{ \begin{bmatrix} a&b&0&c&d&0&0&0&0\\ 0&a&b&0&c&d&0&0&0\\ 0&0&0&a&b&0&c&d&0\\ 0&0&0&0&a&b&0&c&d \end{bmatrix} }_{T(W)} \begin{bmatrix} x_{00}\\x_{01}\\x_{02}\\ x_{10}\\x_{11}\\x_{12}\\ x_{20}\\x_{21}\\x_{22} \end{bmatrix} \]

    从数学上，这已经完全解决卷积了。

    问题是：这个表示对计算机硬件极不友好。

    1. 第一个问题：Toeplitz 矩阵极度稀疏¶

    上面的 \(T(W)\)：

    \[ T(W)\in\mathbb R^{4\times 9} \]

    一共有：

    \[ 4\times9=36 \]

    个元素。

    但其中真正有意义的非零元素只有：

    \[ 4\times4=16 \]

    因为每一个 output pixel 只对应：

    \[ K_hK_w=2\times2=4 \]

    个 kernel weight。

    已经有：

    \[ 20/36\approx55.6\% \]

    是 0。

    而这还是一个极小的 toy example。

    真实 CNN 会严重得多。

    2. 一般情况下 Toeplitz 的稀疏率有多夸张？¶

    先考虑单 input channel、单 output channel。

    输入：

    \[ H_{in}\times W_{in} \]

    输出：

    \[ H_{out}\times W_{out} \]

    kernel：

    \[ K_h\times K_w \]

    那么 Toeplitz 矩阵大小是：

    \[ (H_{out}W_{out}) \times (H_{in}W_{in}) \]

    总元素数：

    \[ N_{\text{total}} = H_{out}W_{out}H_{in}W_{in} \]

    但每个 output 只连接：

    \[ K_hK_w \]

    个输入。

    所以非零元素数：

    \[ N_{\text{nz}} = H_{out}W_{out}K_hK_w \]

    于是非零密度：

    \[ \rho = \frac{N_{\text{nz}}}{N_{\text{total}}} = \frac{K_hK_w}{H_{in}W_{in}} \]

    注意：

    \[ \boxed{ \rho\approx \frac{\text{kernel面积}}{\text{feature map面积}} } \]

    如果输入是：

    \[ 224\times224 \]

    kernel 是：

    \[ 3\times3 \]

    那么：

    \[ \rho \approx \frac{9}{224^2} \approx1.79\times10^{-4} \]

    也就是：

    \[ 0.0179\% \]

    换句话说：

    \[ \boxed{99.982\% \text{ 的矩阵元素都是 }0} \]

    这显然不可能拿普通 dense GEMM 去算。

    3. 第二个问题：kernel 权重被疯狂复制¶

    还是：

    \[ 3\times3 \]

    卷积。

    一个 kernel 只有：

    \[ 9 \]

    个参数。

    但 Toeplitz 矩阵里，每个 output spatial position 都需要一份 kernel。

    如果：

    \[ H_{out}W_{out}=222\times222=49284 \]

    那么这 9 个权重被展开成：

    \[ 9\times49284 = 443556 \]

    个矩阵非零元素。

    注意：

    原本只有 9 个参数，现在为了表达同一个卷积运算，被“逻辑复制”了将近 5 万遍。

    这完全违背了卷积最有价值的性质之一：

    \[ \boxed{\text{weight sharing}} \]

    卷积之所以高效，本来就是因为同一组 kernel 参数被不同 spatial position 重用。

    而显式 Toeplitz：

    把“重用”变成了“复制”。

    这是工程实现里非常糟糕的事情。

    4. 多 channel 情况下问题更加严重¶

    真实卷积：

    \[ X\in\mathbb R^{C_{in}\times H_{in}\times W_{in}} \]
    \[ W\in \mathbb R^{C_{out}\times C_{in}\times K_h\times K_w} \]

    完整 Toeplitz 矩阵：

    \[ T_{\text{full}} \in \mathbb R^{ (C_{out}H_{out}W_{out}) \times (C_{in}H_{in}W_{in}) } \]

    假设一个典型层：

    \[ C_{in}=64 \]
    \[ C_{out}=128 \]
    \[ H_{in}=W_{in}=224 \]
    \[ K_h=K_w=3 \]

    忽略边界细节，近似认为：

    \[ H_{out}=W_{out}=224 \]

    那么 Toeplitz 矩阵行数：

    \[ 128\times224\times224 = 6,422,528 \]

    列数：

    \[ 64\times224\times224 = 3,211,264 \]

    所以整个矩阵大约有：

    \[ 6.42\times10^6 \times 3.21\times10^6 \approx 2.06\times10^{13} \]

    个元素。

    也就是：

    \[ \boxed{20\ \text{trillion级别}} \]

    即使每个元素只用 INT8：

    \[ 2.06\times10^{13}\ \text{Bytes} \]

    大约：

    \[ 20.6\text{ TB} \]

    而原始 kernel 本身只有：

    \[ 128\times64\times3\times3 = 73728 \]

    个参数。

    INT8 下甚至只有：

    \[ 72\text{ KB} \]

    左右。

    于是你得到一个极其荒谬的对比：

    \[ \boxed{ 72\text{ KB 原始权重} \quad\rightarrow\quad \text{十几到几十 TB 的 Toeplitz 表示} } \]

    虽然绝大多数是 0，但即便只存 nonzero，也仍然重复了大量权重。

    5. 那用 sparse matrix 不就行了吗？¶

    这是一个自然问题。

    既然：

    \[ T(W) \]

    很稀疏，那我不用 dense storage，使用 CSR/CSC 之类的 sparse format 行不行？

    数学上当然可以。

    但对卷积这种结构化稀疏来说，这通常仍然很愚蠢。

    因为 CSR 之类格式需要存：

    • value；
    • column index；
    • row pointer。

    但这里的非零位置并不是随机的。

    它们的位置完全由：

    • stride；
    • padding；
    • dilation；
    • kernel size；

    决定。

    例如你本来知道：

    \[ y_{h,w} \]

    一定读取：

    \[ x_{h+k_h,w+k_w} \]

    那为什么还要给每个非零元素额外存一个：

    \[ \text{column index} \]

    呢？

    这相当于：

    明明地址规律可以通过几个加法器直接算出来，却把所有地址索引显式存下来。

    在硬件设计中这是典型的冗余。

    6. 更本质的问题：Toeplitz 把“结构”丢掉了¶

    卷积原本包含非常强的结构信息：

    \[ Y[c_o,h,w] = \sum_{c_i,k_h,k_w} W[c_o,c_i,k_h,k_w] X[c_i,h+k_h,w+k_w] \]

    这里明确知道：

    • 哪些维度是 channel；
    • 哪些维度是 spatial；
    • kernel 在空间上怎么滑；
    • 哪些数据可以复用。

    一旦强行展开成：

    \[ y=T(W)x \]

    就变成一个巨大的 sparse matrix-vector multiplication：

    \[ \text{SpMV} \]

    你反而把很多结构隐藏掉了。

    这对芯片非常不好。

    因为芯片设计最关心的就是：

    \[ \boxed{\text{reuse在哪里？}} \]

    7. Toeplitz 形式其实更接近 GEMV / SpMV，而不是理想 GEMM¶

    注意：

    \[ y=T(W)x \]

    右边 \(x\) 是一个向量。

    所以这其实是：

    \[ \boxed{\text{Matrix-Vector Multiplication}} \]

    即 GEMV。

    如果 Toeplitz 很稀疏，那更准确叫：

    \[ \boxed{\text{Sparse Matrix-Vector Multiplication}} \]

    而现代 CPU/GPU/NPU 最喜欢的通常不是 GEMV，而是：

    \[ \boxed{\text{GEMM}} \]

    即：

    \[ C=AB \]

    为什么？

    因为 GEMM 提供了大量数据复用。

    假设：

    \[ C_{M\times N} = A_{M\times K}B_{K\times N} \]

    一个 \(A_{ik}\) 可以被多个 \(j\) 使用：

    \[ C_{i0},C_{i1},C_{i2},\dots \]

    一个 \(B_{kj}\) 也可以被多个 \(i\) 使用。

    因此非常适合：

    • cache blocking；
    • SIMD；
    • systolic array；
    • tensor core；
    • register reuse；
    • shared SRAM reuse。

    而 GEMV：

    \[ y=Ax \]

    数据复用潜力明显弱很多。

    8. 于是出现一个关键思路：不要展开 kernel，改成展开 input¶

    Toeplitz 做的是：

    把同一个 kernel 在每个 spatial position 的作用全部展开。

    那么能不能反过来？

    既然卷积的每个 output pixel 都是在做：

    \[ \text{kernel} \cdot \text{input patch} \]

    那么我可以：

    1. kernel 只保留一份；
    2. 把所有 input patch 收集起来；
    3. 一次做很多个 dot product。

    这就是 im2col。

    这一步是整个链路中最关键的“视角翻转”。

    9. 从一个 output pixel 开始理解 im2col¶

    还是：

    \[ X= \begin{bmatrix} 1&2&3\\ 4&5&6\\ 7&8&9 \end{bmatrix} \]

    kernel：

    \[ W= \begin{bmatrix} a&b\\ c&d \end{bmatrix} \]

    第一个 output：

    \[ y_{00} = a\cdot1+b\cdot2+c\cdot4+d\cdot5 \]

    把 kernel flatten：

    \[ w= \begin{bmatrix} a&b&c&d \end{bmatrix} \]

    把 patch flatten：

    \[ p_{00} = \begin{bmatrix} 1\\2\\4\\5 \end{bmatrix} \]

    于是：

    \[ y_{00}=wp_{00} \]

    第二个 output：

    \[ y_{01} = a\cdot2+b\cdot3+c\cdot5+d\cdot6 \]

    对应 patch：

    \[ p_{01} = \begin{bmatrix} 2\\3\\5\\6 \end{bmatrix} \]

    所以：

    \[ y_{01}=wp_{01} \]

    同理：

    \[ y_{10}=wp_{10} \]
    \[ y_{11}=wp_{11} \]

    既然同一个 \(w\) 要乘很多个 patch，那么最自然的做法就是：

    \[ \boxed{ [w p_{00},wp_{01},wp_{10},wp_{11}] } \]

    把所有 patch 横向拼起来：

    \[ X_{\text{col}} = \begin{bmatrix} 1&2&4&5\\ 2&3&5&6\\ 4&5&7&8\\ 5&6&8&9 \end{bmatrix} \]

    于是：

    \[ \boxed{ Y_{\text{row}} = wX_{\text{col}} } \]

    即：

    \[ \begin{bmatrix} y_{00}&y_{01}&y_{10}&y_{11} \end{bmatrix} = \begin{bmatrix} a&b&c&d \end{bmatrix} \begin{bmatrix} 1&2&4&5\\ 2&3&5&6\\ 4&5&7&8\\ 5&6&8&9 \end{bmatrix} \]

    这就是 im2col 最基本的形式。

    10. 为什么叫 im2col？¶

    名字其实很直白：

    \[ \text{image to columns} \]

    即：

    把 image 中每一个 receptive field 展开成一列。

    例如：

    Input image

1 2 3
4 5 6
7 8 9

    四个 \(2\times2\) patch：

    1 2    2 3    4 5    5 6
4 5    5 6    7 8    8 9

    分别 flatten：

    [1]    [2]    [4]    [5]
[2]    [3]    [5]    [6]
[4]    [5]    [7]    [8]
[5]    [6]    [8]    [9]

    然后并排：

    \[ X_{\text{col}} = \begin{bmatrix} 1&2&4&5\\ 2&3&5&6\\ 4&5&7&8\\ 5&6&8&9 \end{bmatrix} \]

    所以名字就叫：

    \[ \boxed{\text{im2col}} \]

    11. Toeplitz 和 im2col 究竟是什么关系？¶

    这是这一阶段最值得理解清楚的问题。

    Toeplitz：

    \[ y=T(W)x \]

    是在复制、平移：

    \[ \boxed{\text{weight}} \]

    im2col：

    \[ y=WX_{\text{col}} \]

    是在复制、收集：

    \[ \boxed{\text{input patch}} \]

    两者是完全相同卷积的两种展开方法。

    可以理解成：

                        Convolution
                        |
          +-------------+-------------+
          |                           |
          v                           v
   展开 kernel 的位置             展开 input patch
          |                           |
          v                           v
      Toeplitz                    im2col
          |                           |
          v                           v
       T(W)x                      W Xcol

    二者的每一个乘法实际上是一一对应的。

    12. 为什么 im2col 比 Toeplitz 好很多？¶

    关键原因之一：

    \[ \boxed{\text{把稀疏运算变成 dense 运算}} \]

    Toeplitz：

    \[ T(W) \]

    里面大量是 0。

    而 im2col：

    \[ X_{\text{col}} \]

    几乎全部是有用的输入数据。

    kernel matrix：

    \[ W_{\text{mat}} \]

    也全部是有效权重。

    于是：

    \[ W_{\text{mat}}X_{\text{col}} \]

    变成真正 dense GEMM。

    这非常适合现代计算硬件。

    13. 多 input channel 时 im2col 怎么做？¶

    假设：

    \[ C_{in}=2 \]

    kernel：

    \[ 2\times2 \]

    那么一个 receptive field 实际大小是：

    \[ C_{in}\times K_h\times K_w = 2\times2\times2 = 8 \]

    例如两个 channel：

    \[ X_0= \begin{bmatrix} 1&2&3\\ 4&5&6\\ 7&8&9 \end{bmatrix} \]
    \[ X_1= \begin{bmatrix} 10&11&12\\ 13&14&15\\ 16&17&18 \end{bmatrix} \]

    第一个 receptive field 包括：

    channel 0：

    \[ \begin{bmatrix} 1&2\\ 4&5 \end{bmatrix} \]

    channel 1：

    \[ \begin{bmatrix} 10&11\\ 13&14 \end{bmatrix} \]

    flatten 后：

    \[ p_{00} = \begin{bmatrix} 1\\2\\4\\5\\10\\11\\13\\14 \end{bmatrix} \]

    长度正是：

    \[ C_{in}K_hK_w=8 \]

    每一个 output spatial position 都产生这样一个向量。

    14. 多 output channel 时自然形成 GEMM¶

    假设：

    \[ C_{out}=3 \]

    每个 output channel 都有自己的 kernel：

    \[ W_0,W_1,W_2 \]

    每个 kernel flatten 成一行：

    \[ w_0^T \]
    \[ w_1^T \]
    \[ w_2^T \]

    然后堆起来：

    \[ W_{\text{mat}} = \begin{bmatrix} - & w_0^T & -\\ - & w_1^T & -\\ - & w_2^T & - \end{bmatrix} \]

    因此：

    \[ W_{\text{mat}} \in \mathbb R^{ C_{out}\times(C_{in}K_hK_w) } \]

    所有 input patch：

    \[ X_{\text{col}} \in \mathbb R^{ (C_{in}K_hK_w) \times (H_{out}W_{out}) } \]

    于是：

    \[ \boxed{ Y_{\text{mat}} = W_{\text{mat}}X_{\text{col}} } \]

    尺寸就是：

    \[ \boxed{ [C_{out}\times(C_{in}K_hK_w)] \times [(C_{in}K_hK_w)\times(H_{out}W_{out})] } \]

    得到：

    \[ \boxed{ [C_{out}\times(H_{out}W_{out})] } \]

    最后 reshape 回：

    \[ C_{out}\times H_{out}\times W_{out} \]

    这就是标准的卷积 → GEMM。

    15. 现在可以定义标准 GEMM 的 M、N、K¶

    以后看 accelerator 文献时经常直接把卷积写成：

    \[ [M\times K][K\times N] \]

    对于普通卷积：

    \[ \boxed{ M=C_{out} } \]
    \[ \boxed{ K=C_{in}K_hK_w } \]
    \[ \boxed{ N=H_{out}W_{out} } \]

    所以：

    \[ \boxed{ [M\times K] \times [K\times N] = [M\times N] } \]

    也就是：

    \[ W_{\text{mat}} X_{\text{col}} = Y_{\text{mat}} \]

    这三个字母以后会一直出现。

    16. 从循环角度看 im2col 为什么等价¶

    普通卷积：

    \[ Y[c_o,h,w] = \sum_{c_i,k_h,k_w} W[c_o,c_i,k_h,k_w] X[c_i,h+k_h,w+k_w] \]

    把：

    \[ (c_i,k_h,k_w) \]

    合并成 GEMM 的：

    \[ k \]

    把：

    \[ (h,w) \]

    合并成：

    \[ n \]

    再令：

    \[ c_o\rightarrow m \]

    那么就变成：

    \[ Y[m,n] = \sum_k W[m,k]X_{\text{col}}[k,n] \]

    即：

    \[ \boxed{ C_{mn} = \sum_k A_{mk}B_{kn} } \]

    这就是标准矩阵乘法。

    所以本质上：

    \[ \boxed{ \text{Conv}\rightarrow\text{GEMM} } \]

    主要就是一次维度重组：

    \[ (c_o,c_i,k_h,k_w,h,w) \]

    重解释为：

    \[ (M,K,N) \]

    17. 为什么 GEMM 对计算机这么友好？¶

    这是从数学过渡到硬件的真正原因。

    一个 GEMM：

    \[ C=AB \]

    内部操作是大量：

    \[ c_{ij} += a_{ik}b_{kj} \]

    它的特点是：

    计算规则高度统一¶

    全部都是：

    \[ \boxed{\text{MAC}} \]

    即 multiply-accumulate。

    权重可以重用¶

    固定：

    \[ A_{ik} \]

    它会参与：

    \[ C_{i0},C_{i1},\dots,C_{iN-1} \]

    所以一个 weight 可以服务多个 spatial output。

    activation 也可以重用¶

    固定：

    \[ B_{kj} \]

    它会服务：

    \[ C_{0j},C_{1j},\dots,C_{M-1,j} \]

    也就是被多个 output channel 使用。

    很容易 tile¶

    例如：

    \[ 128\times576 \]

    乘：

    \[ 576\times50176 \]

    可以切成：

    \[ 16\times16 \]

    或者：

    \[ 32\times32 \]

    的小 block。

    这正适合有限大小的：

    • register file；
    • SRAM；
    • cache；
    • systolic array。

    18. 一个很重要的工程变化：从 SpMV 变成 GEMM¶

    现在比较一下。

    Toeplitz 视角：

    \[ \boxed{ y=T(W)x } \]

    本质接近：

    \[ \text{sparse matrix-vector} \]

    特点：

    • 大量 0；
    • 权重重复；
    • metadata 冗余；
    • 不适合 dense MAC array；
    • reuse 结构被隐藏。

    而 im2col：

    \[ \boxed{ Y=W_{\text{mat}}X_{\text{col}} } \]

    本质是：

    \[ \text{dense matrix-matrix} \]

    特点：

    • 没有结构性的 0；
    • kernel 只保留一次；
    • 适合 BLAS；
    • 适合 SIMD；
    • 适合 GPU Tensor Core；
    • 适合 systolic array。

    所以这是一个非常重要的转换：

    \[ \boxed{ \text{Sparse structured operator} \rightarrow \text{Dense GEMM} } \]

    19. 但是 im2col 也付出了代价¶

    到这里千万不要产生一个误解：

    im2col 完美解决了问题。

    并没有。

    它只是把 Toeplitz 的问题换成了另一个问题。

    Toeplitz 的问题是：

    \[ \boxed{\text{复制 weight + 存很多 0}} \]

    im2col 的问题是：

    \[ \boxed{\text{复制 activation}} \]

    看刚才例子：

    原始：

    \[ X= \begin{bmatrix} 1&2&3\\ 4&5&6\\ 7&8&9 \end{bmatrix} \]

    只有：

    \[ 9 \]

    个元素。

    但：

    \[ X_{\text{col}} = \begin{bmatrix} 1&2&4&5\\ 2&3&5&6\\ 4&5&7&8\\ 5&6&8&9 \end{bmatrix} \]

    有：

    \[ 16 \]

    个元素。

    比如中心元素 5 出现了：

    \[ 4 \]

    次。

    这不是偶然。

    20. 为什么 input 会重复？¶

    因为相邻 convolution windows 高度重叠。

    对于 stride=1 的：

    \[ 3\times3 \]

    卷积，一个 interior input pixel 会被周围最多：

    \[ 3\times3=9 \]

    个 output receptive fields 使用。

    所以 im2col 会把它逻辑复制接近 9 次。

    更一般地：

    \[ |X_{\text{col}}| = C_{in}K_hK_wH_{out}W_{out} \]

    原始输入：

    \[ |X| = C_{in}H_{in}W_{in} \]

    若：

    \[ H_{out}\approx H_{in} \]
    \[ W_{out}\approx W_{in} \]

    那么：

    \[ \frac{|X_{\text{col}}|}{|X|} \approx K_hK_w \]

    所以：

    \[ 3\times3 \Rightarrow \sim9\times \]
    \[ 5\times5 \Rightarrow \sim25\times \]

    这是非常明显的数据膨胀。

    21. 用一个真实尺寸量化 im2col 膨胀¶

    假设：

    \[ C_{in}=64 \]
    \[ H=W=224 \]
    \[ K=3\times3 \]

    输入元素数量：

    \[ 64\times224\times224 = 3,211,264 \]

    如果 FP16：

    \[ \approx6.4\text{ MB} \]

    而 im2col 大约：

    \[ 64\times3\times3\times224\times224 \]

    即：

    \[ 28,901,376 \]

    个元素。

    FP16：

    \[ \approx57.8\text{ MB} \]

    几乎：

    \[ 9\times \]

    膨胀。

    而且这只是一个中间临时 tensor。

    22. 对芯片而言，为什么这个问题严重？¶

    因为现代 AI 芯片中最昂贵的往往不是：

    \[ \text{multiply} \]

    而是：

    \[ \boxed{\text{data movement}} \]

    例如：

    DRAM
  ↓
load input
  ↓
构造 Xcol
  ↓
write Xcol
  ↓
read Xcol
  ↓
MAC array

    这里发生了大量：

    • extra write；
    • extra read；
    • SRAM capacity consumption；
    • DRAM bandwidth consumption；
    • address generation；
    • energy consumption。

    也就是说：

    为了让计算看起来像漂亮的 GEMM，我们人为制造了一个巨大的中间矩阵。

    这是软件层面很方便，但硬件层面很不理想。

    23. 这就为下一阶段埋下了伏笔¶

    现在我们已经经历两次表示：

    第一种：

    \[ \boxed{ y=T(W)x } \]

    问题：

    \[ \text{Toeplitz 巨大、稀疏、weight重复} \]

    第二种：

    \[ \boxed{ Y=W_{\text{mat}}X_{\text{col}} } \]

    优点：

    \[ \text{dense GEMM} \]

    但问题：

    \[ \text{activation被重复物化} \]

    于是下一个非常自然的问题就是：

    既然 \(X_{\text{col}}\) 里的值本质上都来自原始 \(X\)，而且位置关系完全可计算，为什么一定要真的把 \(X_{\text{col}}\) 写出来？

    答案就是：

    \[ \boxed{\text{不需要。}} \]

    这会进入下一阶段：

    \[ \boxed{\text{implicit GEMM}} \]

    也就是：

    数学上仍然按照 im2col + GEMM 来理解和调度，但物理上不真正生成 \(X_{\text{col}}\)。

    24. 这一阶段最重要的逻辑链¶

    建议你把这条链记牢：

    \[ \boxed{ \text{Conv} } \]

    ↓

    \[ \boxed{ y=T(W)x } \]

    Toeplitz 暴露出卷积是线性算子，但：

    \[ \text{稀疏 + weight复制 + 矩阵巨大} \]

    ↓

    于是换一个展开方向：

    \[ \boxed{ Y=W_{\text{mat}}X_{\text{col}} } \]

    得到：

    \[ \text{dense GEMM} \]

    ↓

    但：

    \[ X_{\text{col}} \]

    大量复制 activation

    ↓

    于是进一步：

    \[ \boxed{ \text{implicit im2col / implicit GEMM} } \]

    即：

    \[ \boxed{ \text{保留 GEMM 的计算结构，但消灭显式 }X_{\text{col}} } \]

    你现在可以把 Toeplitz 和 im2col 看成两个“极端”：

    方法 谁被展开/复制 优点 核心缺点
    Toeplitz Kernel 数学最直观 大量 0、weight 巨量重复
    im2col Input patch 变成 dense GEMM activation 大量重复
    implicit GEMM 都不显式复制 保留 GEMM 友好性 地址生成和数据调度复杂

    下一阶段，我们就可以正式进入 explicit im2col → implicit GEMM。届时最重要的是把下面这个东西讲透：

    \[ X_{\text{col}}[k,n] \]

    到底如何直接映射回：

    \[ X[c_i,h_{in},w_{in}] \]

    也就是硬件怎样根据 \(k,n\) 实时算出原始 activation 地址，并把它送入 GEMM/MAC 阵列。这一步开始，就真正进入 AI 加速器实现层面了。
